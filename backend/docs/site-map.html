Trusta AST — Site Map

This document uses a Mermaid diagram to show the page architecture of the frontend SPA (Trusta-AST-Frontend): which pages exist, and which functional blocks each page contains.

Sources: the built SPA bundle (routes / chunks), the backend API endpoints, and cross-referencing with the finetune_manual.html / inference_manual.html user manuals. Blocks are shown at panel-level granularity.

No Settings page. apiBaseUrl and enabledEngines are read once from config.json at boot and are not editable from the UI. The only "Settings" in the interface is a Chat Settings popover for generation parameters, inside the Inference page.

GGUF conversion is backend-only. The backend exposes POST /config/models/convert and GET /config/models/convert/{job_id}, but the shipped SPA never calls them — the Models page only uses /config/models, /config/models/download, /config/models/downloads and DELETE /config/models/{label}.
Note: the frontend source code is not part of this repo (only the dist/ and dist_client/ build artifacts), so the pages and routes were confirmed from bundle chunk names (fine-tuning-page, models-page) and route strings, while the block contents were inferred from the backend APIs and the user manuals.
